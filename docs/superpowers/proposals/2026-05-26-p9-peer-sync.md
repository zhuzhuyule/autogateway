## P9.0 详细 Spec — 同步基础设施补齐

### Gap 1: 同步死循环防御

**现状**:`app.go:175` 注释里写了 "Avoid infinite loop if this was a sync merge transaction by checking a context flag?",但**没有实现**。A 推给 B → B 合并 → GORM hook 触发 → B 又推回 A → A 合并 → 再推 B…… LWW 时间戳会在 `incoming.UpdatedAt == existing.UpdatedAt` 时停止 Save,所以**数据最终一致**,但中间会产生大量空 push 噪音 + `sync_logs` 爆量。

**方案**:
```go
// services/sync_service.go ProcessPayload 开头
type syncMergeKey struct{}
ctx = context.WithValue(ctx, syncMergeKey{}, true)

// app.go notifyFunc
notifyFunc := func(tx *gorm.DB) {
    if v, _ := tx.Statement.Context.Value(syncMergeKey{}).(bool); v {
        return // 合并事务,不再 notify
    }
    a.syncPeerManager.NotifyChange()
}
```

### Gap 2: WS server 端鉴权

**现状**:`WsEndpoint:48` 只校验本端 `SyncEnabled` + `SyncKey` 非空,**不校验对端身份**。任何能到达 `/api/sync/ws` 的客户端都能推密文,密文解密失败只刷错误日志,通道仍开放,有 DoS 与 oracle 风险。`CheckOrigin: return true` 接受任意 Origin。

**方案**:
- WS 握手期间在 `Sec-WebSocket-Protocol` 或自定义 header(`X-Sync-Key`)里带 peer.SyncKey,服务端比对失败即拒绝 upgrade。
- `CheckOrigin` 改成基于 `peers` 表的允许列表(查询 peer.URL 的 host 部分匹配)。

### Gap 3: WS 双向化

**现状**:proposal 说"任何一端发生配置修改立即通过 WebSocket 向所有已连接的对端广播",但实现里:
- client (`peer_manager`) 持有 conn,WriteMessage 推数据,ReadMessage 只用来检测断开
- server (`handler`) 持有 conn,ReadMessage 收数据,**从不 WriteMessage**

结果:server 端的本地变更**没法通过 ws 推回 client**,只能等 client 5 分钟一次的 pull。违背"双向毫秒级触达"。

**方案**:`SyncHandler.clients` 集合在收到本端 `NotifyChange` 时遍历所有 ws 写入。即在 `SyncHandler` 里挂一个 goroutine 监听 `peer_manager` 的 push 事件,把同样的密文也写到所有 server 端 conn。

### Gap 4: `lastPushTime` 持久化

**现状**:`peer_manager.go:41` 初始化为 `time.Now().Add(-24h)`,**进程重启就重置**。如果上次同步在 3 天前,中间变更全部丢失(因为下次 push 只带 24h 内变更)。

**方案**:改用 `peers.last_synced_at`(已存在),每次 push 成功后更新;启动时取每个 peer 的 `last_synced_at` 作为各自的 since。

### Gap 5: SyncLog 写入

**现状**:表定义了,`Create(&SyncLog{...})` 在代码里 grep 不到一处。`sync_handler.go` / `peer_manager.go` 里所有 push/pull 成功失败都只 `logrus.Info/Error`,**没落库**。

**方案**:在以下 6 个点写 `SyncLog`:
1. `peer_manager.pushToPeers` 成功 → `action=push, status=success, details=table counts`
2. `peer_manager.pushToPeers` 失败 → `action=push, status=error, error_message=...`
3. `peer_manager.doPull` 成功 → `action=pull, status=success`
4. `peer_manager.doPull` 失败 → `action=pull, status=error`
5. `sync_handler.WsEndpoint` 收 push 成功 → `action=push, status=success, peer_id=source`
6. `sync_handler.WsEndpoint` 处理失败 → `action=push, status=error`

加一行 retention:启动时 `DELETE FROM sync_logs WHERE timestamp < NOW() - 30 days`。

### Gap 6: SyncKey 职责拆分

**现状**:
- 加密用**本端** `settings.SyncKey`(全局单值)
- HTTP 鉴权用**每个 peer** 自带的 `peer.SyncKey`
- WS 完全没用 `peer.SyncKey`

意味着所有 mesh 节点必须共享同一个全局 `SyncKey`(加密对称密钥),同时每个 peer 又有各自的 key 用来鉴权——两套密钥同时存在但用途含糊。

**方案**(明确化,不变现有结构):
- `settings.SyncKey` = **AES-GCM 加密用全局密钥**,所有节点必须一致;UI 里改名为 `SyncSecret` 以区分。
- `peer.SyncKey` = **该 peer 的入门 token**,WS 握手 + HTTP pull 鉴权都用它,**每个 peer 唯一**。
- 文档化两者的区别(README + UI 说明)。

#### Schema fingerprint

启动时遍历 `SyncPayload` 涉及的 5 个 model(SystemSetting/Group/GroupSubGroup/ModelAlias/APIKey),提取所有 GORM 字段名 + 类型 → SHA256 → 取前 12 字节十六进制 = `schema_hash`。

```go
// services/schema_fingerprint.go (新增)
func ComputeSchemaHash() string {
    var fields []string
    for _, m := range []interface{}{
        models.SystemSetting{}, models.Group{}, models.GroupSubGroup{},
        models.ModelAlias{}, models.APIKey{},
    } {
        // reflect 拉字段名+类型,排序拼接
    }
    sort.Strings(fields)
    h := sha256.Sum256([]byte(strings.Join(fields, "|")))
    return hex.EncodeToString(h[:6])
}
```

任何 model 字段增减都会改变 hash → 两端不一致即可探测。

#### WS 握手协议

```
client → server (first frame): {"type":"hello","version":"v2.4.10","schema_hash":"a1b2c3d4e5f6","sync_key":"<peer.SyncKey>"}
```

## P9.2 详细 Spec — 远程升级 (信号文件 + 宿主机 Watcher)

### 核心约束

**Docker 容器内进程无法重启自己**,且把 `/var/run/docker.sock` 挂进主容器 = 等于把宿主机 root 权限交给容器(严重 anti-pattern)。所以采用**信号文件 + 宿主机 watcher**:

```
容器内 Go 进程 → 写 /app/data/.upgrade-request
                              ↓ (./data 已经挂载到宿主机)
宿主机 watcher (systemd 或独立容器) → 读文件 → docker compose pull && up -d
```

主容器**零特权**,只多写一个文件;升级权限隔离在 watcher 里。

### 容器侧改动

#### `internal/services/upgrade_service.go` (新增)

```go
type UpgradeService struct {
    db           *gorm.DB
    currentVer   string
    signalPath   string // "/app/data/.upgrade-request"
    logger       *logrus.Entry
}

type UpgradeRequest struct {
    TargetVersion string    `json:"target_version"`
    RequestedBy   string    `json:"requested_by"`   // peer_id 或 "self"
    RequestedAt   time.Time `json:"requested_at"`
}

func (s *UpgradeService) RequestUpgrade(req UpgradeRequest) error {
    // 安全限制 1: 不允许降级
    if compareVersions(req.TargetVersion, s.currentVer) < 0 {
        return errors.New("downgrade not allowed")
    }
    // 安全限制 2: 必须是有效的 semver tag
    if !semverRegex.MatchString(req.TargetVersion) {
        return errors.New("invalid version format")
    }
    // 安全限制 3: 已有 pending 升级时拒绝(防 DoS)
    if _, err := os.Stat(s.signalPath); err == nil {
        return errors.New("upgrade already pending")
    }

    payload, _ := json.Marshal(req)
    return os.WriteFile(s.signalPath, payload, 0o600)
}
```

#### WS message 扩展

```
client → peer (跨节点触发): {"type":"upgrade_request","target_version":"v2.4.10","by":"<self_peer_id>"}
peer → client (回复): {"type":"upgrade_ack","accepted":true} 或 {"accepted":false,"reason":"..."}
```

#### UI

`Sync.vue` 的每行 peer,如果 `peer.version < my.version` 且 `schema_hash` 一致:
- 显示 "升级到 vX.Y.Z" 按钮

### 宿主机侧产物

#### 选项 A — `examples/upgrader.sh` + systemd service

```bash
#!/bin/bash
# /opt/autogateway/upgrader.sh
set -euo pipefail

SIGNAL=/opt/autogateway/data/.upgrade-request
LOG=/opt/autogateway/data/.upgrade-log

while true; do
  if [ -f "$SIGNAL" ]; then
    target=$(jq -r '.target_version' "$SIGNAL")
    echo "$(date -Iseconds)|start|$target" >> "$LOG"
    rm "$SIGNAL"
    
    cd /opt/autogateway
    if docker compose pull && docker compose up -d; then
      echo "$(date -Iseconds)|success|$target" >> "$LOG"
    else
      echo "$(date -Iseconds)|failed|$target" >> "$LOG"
    fi
  fi
  sleep 10
done
```

```ini
# /etc/systemd/system/autogateway-upgrader.service
[Unit]
Description=AutoGateway Upgrade Watcher
After=docker.service

[Service]
Type=simple
ExecStart=/opt/autogateway/upgrader.sh
Restart=always
RestartSec=5

[Install]
```
